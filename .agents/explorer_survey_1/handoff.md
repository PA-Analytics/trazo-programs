## 2. Logic Chain

1. **Premise:** The user request (`ORIGINAL_REQUEST.md`) and design system (`DESIGN.md`) require a physical 2.5D companion that inhabits the React Flow quest map canvas, moves along real SVG edges, supports 5 states, and opens an anchored conversation popover without cluttering the screen with permanent large overlays.
2. **Observation Step 1:** All mathematical and kinematic foundations for the companion (`CompanionAvatar`, `useCompanionTraveler`, `CompanionPathSampler`, `QuestEdge` spline math) are already built, typed, and style-compliant with the mineral paper / cobalt palette in `trazo-tokens.css` and `companion.css`.
3. **Observation Step 2:** React Flow renders nodes inside a CSS transform viewport layer (`.react-flow__viewport`). Placing `CompanionAvatar` into this viewport coordinate space enables hardware-accelerated zoom and pan scaling without any manual canvas-to-screen matrix transformations.
4. **Observation Step 3:** The edge geometries generated by `QuestEdge` (`smoothSplineThroughVia` and `getBezierPath`) can be sampled deterministically by `CompanionPathSampler` given the source and target node coordinates and intermediate `via` points.
5. **Observation Step 4:** The existing test suite (75 passing tests) validates all backend API endpoints (`/api/v1/implementations/:id/next-action`, `/submissions`, `/start-mission`), rubrics, and state transitions.
6. **Conclusion Step:** Integrating `CompanionAvatar` into `QuestMapCanvas` and connecting its travel method to mission transitions and next-action recommendations completes the 2.5D physical inhabitation requirement with zero regressions to the existing test and typecheck baseline.

## 3. Caveats

1. **React Flow DOM Mounting Container:** In `@xyflow/react`, when placing elements inside the viewport layer, ensuring the element receives pointer events (`pointer-events: auto`) while the background pane remains draggable (`panOnDrag`) requires verifying DOM event propagation stops (`event.stopPropagation()` on the mascot and anchored panel).
2. **Multi-Chapter Scalability:** Currently, Chapter 1 (`chapter-1`) is the only active chapter with full topological coordinates and nodes (`N01` through `N09`). Subsequent chapters will follow the same coordinate and edge schema.
3. **External LLM Network Calls:** Diagnostic tests marked with `# SKIP` in `npm test` are live Vertex AI tests requiring GCP credentials, while all unit, mock, and policy tests (75 tests) run entirely locally in <5.5s.
